Certificate Types
1. Self-Signed Certificates (Development/Testing)
Generated by the generate-certs.sh script

For local development and testing only

Browsers will show security warnings

Valid for 365 days

2. CA-Signed Certificates (Staging/Production)
Issued by a trusted Certificate Authority (CA)

Required for production environments

No browser warnings

Usually valid for 90 days (Let's Encrypt) or 1-2 years (commercial CAs)

Quick Start
Generate Self-Signed Certificates (Development)
bash
# Navigate to SSL directory
cd deployment/docker/nginx/ssl

# Make the script executable
chmod +x generate-certs.sh

# Generate certificates
./generate-certs.sh
This will create:

key.pem: Private key (2048-bit RSA)

cert.pem: Self-signed certificate (valid for 365 days)

Verify Generated Certificates
bash
# View certificate details
openssl x509 -in cert.pem -text -noout

# Verify certificate against private key
openssl x509 -noout -modulus -in cert.pem | openssl md5
openssl rsa -noout -modulus -in key.pem | openssl md5
# Both should output the same MD5 hash
Production Deployment
Option 1: Let's Encrypt (Recommended for Production)
bash
# Using Certbot (example for Ubuntu/Debian)
sudo apt-get update
sudo apt-get install certbot

# Generate certificates
sudo certbot certonly --standalone \
  -d yourdomain.com \
  -d api.yourdomain.com \
  -d dashboard.yourdomain.com \
  --email admin@yourdomain.com \
  --agree-tos \
  --non-interactive

# Copy certificates to SSL directory
sudo cp /etc/letsencrypt/live/yourdomain.com/fullchain.pem deployment/docker/nginx/ssl/cert.pem
sudo cp /etc/letsencrypt/live/yourdomain.com/privkey.pem deployment/docker/nginx/ssl/key.pem

# Set proper permissions
sudo chmod 600 deployment/docker/nginx/ssl/key.pem
sudo chmod 644 deployment/docker/nginx/ssl/cert.pem
Option 2: Commercial CA Certificates
Generate a Certificate Signing Request (CSR):

bash
openssl req -new -key key.pem -out csr.pem \
  -subj "/C=US/ST=State/L=City/O=Parking Management Inc./CN=yourdomain.com"
Submit CSR to your CA (DigiCert, Comodo, etc.)

Install the issued certificates:

Place the CA's certificate in cert.pem

Keep your private key in key.pem

Include intermediate certificates if provided

Option 3: Load Balancer/Cloud Provider Certificates
For AWS, Google Cloud, Azure, or other cloud providers:

Generate or upload certificates through your cloud provider's console

Reference them in your load balancer configuration

Update NGINX config to terminate SSL at the load balancer

NGINX Configuration
The main NGINX configuration (nginx.conf) is set up to use these certificates:

nginx
ssl_certificate /etc/nginx/ssl/cert.pem;
ssl_certificate_key /etc/nginx/ssl/key.pem;
Certificate Management
Renewal (Let's Encrypt)
bash
# Manual renewal
sudo certbot renew

# Auto-renewal with cron (add to crontab)
0 0 */7 * * certbot renew --quiet && systemctl reload nginx
Rotation
When updating certificates:

bash
# 1. Generate new certificates
./generate-certs.sh.new

# 2. Test new certificates
nginx -t

# 3. Replace old certificates
mv cert.pem cert.pem.old
mv key.pem key.pem.old
mv cert.pem.new cert.pem
mv key.pem.new key.pem

# 4. Reload NGINX
docker-compose -f ../docker-compose.yml exec nginx nginx -s reload
Backup
bash
# Backup SSL certificates
tar -czf ssl-backup-$(date +%Y%m%d).tar.gz *.pem

# Store backups securely (encrypted)
gpg -c ssl-backup-$(date +%Y%m%d).tar.gz
Security Best Practices
1. Private Key Protection
bash
# Set restrictive permissions
chmod 600 key.pem

# Store private key securely
# Never commit to version control
# Use environment variables or secret management tools in production
2. Key Rotation Schedule
Development: Every 6-12 months

Production: Follow CA validity period (90 days for Let's Encrypt)

After security incidents: Immediately

3. Certificate Monitoring
Monitor certificate expiration:

bash
# Check expiration date
openssl x509 -in cert.pem -dates -noout

# Script to check and alert
./check-cert-expiry.sh
4. Cipher Suite Configuration
Ensure strong ciphers in NGINX config:

nginx
ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:DHE-RSA-AES256-GCM-SHA512;
ssl_prefer_server_ciphers on;
Troubleshooting
Common Issues
1. Certificate Not Trusted
text
ERR_CERT_AUTHORITY_INVALID
Solution: For production, use CA-signed certificates. For development, import the self-signed certificate to your trusted store.

2. Private Key Mismatch
text
SSL: error:0B080074:x509 certificate routines:X509_check_private_key:key values mismatch
Solution: Ensure cert.pem and key.pem are a matching pair.

3. Certificate Expired
text
ERR_CERT_DATE_INVALID
Solution: Renew certificates before they expire.

4. Wrong Domain
text
ERR_CERT_COMMON_NAME_INVALID
Solution: Ensure certificate Common Name (CN) matches your domain.

Diagnostic Commands
bash
# Test SSL connection
openssl s_client -connect localhost:443 -servername yourdomain.com

# Check certificate chain
openssl s_client -connect localhost:443 -showcerts

# Verify certificate against domain
openssl s_client -connect localhost:443 -servername yourdomain.com 2>/dev/null | openssl x509 -noout -subject -issuer -dates
Development vs Production
Aspect	Development	Production
Certificate Type	Self-signed	CA-signed (Let's Encrypt or commercial)
Validity	365 days	90 days (LE) or 1-2 years
Browser Trust	Security warnings	Fully trusted
Renewal	Manual	Automated
Key Storage	Local files	Secret management (Vault, KMS, etc.)
Backup	Optional	Required with encryption
Automated Certificate Management
Using Docker Secrets
bash
# Create Docker secrets
echo "your-private-key-content" | docker secret create ssl_key -
echo "your-certificate-content" | docker secret create ssl_cert -

# Update docker-compose.yml to use secrets
nginx:
  image: nginx:alpine
  secrets:
    - ssl_key
    - ssl_cert
  volumes:
    - type: bind
      source: /run/secrets/ssl_key
      target: /etc/nginx/ssl/key.pem
      read_only: true
Using Kubernetes Secrets
yaml
apiVersion: v1
kind: Secret
metadata:
  name: ssl-certificate
type: kubernetes.io/tls
data:
  tls.crt: base64-encoded-certificate
  tls.key: base64-encoded-private-key
Emergency Procedures
Certificate Compromise
If private key is compromised:

Immediately:

bash
# Revoke certificates
certbot revoke --cert-path cert.pem --reason keycompromise

# Generate new key pair
openssl genrsa -out key.pem.new 4096
Notify stakeholders

Investigate breach

Update all systems using the compromised key

Certificate Expiry Emergency
bash
# Quick renewal
certbot renew --force-renewal

# Temporary solution (development only)
./generate-certs.sh
systemctl reload nginx
